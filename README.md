## Features

- 🗳️ **Three-option voting** — cast your ballot for Option A, B, or C
- 🔒 **Zero-knowledge voter identity** — your identity never touches the chain; only a nullifier commitment is stored publicly
- 🚫 **Double-vote prevention** — each secret key can only produce one valid nullifier per proposal
- 📊 **Live tally** — vote counts are public and update in real time
- 🌐 **Wallet integration** — connects to Midnight Lace wallet via the DApp Connector API
- 🖥️ **CLI + UI** — interact via a rich React frontend or a Node.js command-line interface

---

## What This Project Does

VoteDApp allows anyone to create a confidential on-chain voting proposal on the Midnight blockchain. Voters cast their ballots anonymously — the on-chain record shows only that *someone* voted (via a nullifier commitment), but the link between ballot and identity is impossible to reconstruct without the voter's secret key.

The vote tally (how many votes each option received) is fully public. What stays private is *who voted for what*.

---

## Privacy Model

| Data | Visibility |
|------|-----------|
| Proposal title | **Public** — stored on-chain |
| Vote counts (A / B / C) | **Public** — updated on every ballot |
| Total votes cast | **Public** |
| Voter identity | **Private** — never stored on-chain |
| Which option a voter chose | **Public** via tally (individual attribution impossible) |
| Nullifier | **Public commitment** — proves uniqueness without revealing identity |

### What voters prove without revealing

Using Midnight's zero-knowledge proof system, a voter proves:

1. They know a secret key that hashes to a specific nullifier.
2. That nullifier has not been registered on-chain before (no double-voting).
3. The correct vote tally counter is incremented.

No one — not even the contract deployer — can determine which voter cast which ballot.

## Tech Stack

| Layer | Technology |
|-------|-----------|
| Smart Contract | Compact (Midnight ZK DSL) |
| ZK Proof System | Midnight built-in (circuit-per-vote design) |

| Build tooling | npm workspaces + TypeScript |

## Compile

Compile the Compact contract (generates ZK circuits, keys, and TypeScript bindings):

```bash
cd contract
compact compile src/voting.compact ./src/managed/voting
```

Or use the npm script:

```bash
cd contract && npm run compact
```

## After Deployment

Once you have deployed the contract and received a contract address, perform these three steps:

1. **Deploy** the Compact contract (run the command above).
2. **Copy** the deployed contract address from the output.
3. **Replace** every occurrence of `<YOUR_DEPLOYED_CONTRACT_ADDRESS>` in:
   - `voting-ui/.env.preprod` → `CONTRACT_ADDRESS=<address>`
   - `voting-ui/src/main.tsx` → comment at the top
   - This `README.md` → the Contract Address table above

No additional coding is required.

## Troubleshooting

### "Could not find Midnight Lace wallet"
- Install the Midnight Lace extension from the official source.
- Ensure the extension is enabled and connected to the `preprod` network.

### Proof server not running
```bash
docker run -p 6300:6300 midnightnetwork/proof-server
```

### Build fails with "managed/voting not found"
Run the compact compiler first:
```bash
cd contract && compact compile src/voting.compact ./src/managed/voting
```

### Node.js out of memory during deploy
```bash
NODE_OPTIONS="--max-old-space-size=12288" npm run deploy -- --network preprod
```

### Typecheck errors after modifying contract
Recompile the contract and rebuild the contract package:
```bash
cd contract && npm run compact && npm run build
```

### "Already voted" error
Your nullifier is already registered on-chain. Each secret key can only vote once per proposal. Create a new wallet or join a different proposal.
